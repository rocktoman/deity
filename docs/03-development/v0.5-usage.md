# Deity V0.5 使用说明

V0.5 增加 Plan/Build、Code Intelligence、Git Guard 与 Verification。所有新能力默认关闭；配置开关不会扩大已有权限，工作区边界也不是操作系统沙箱。

## 1. 配置

```toml
[coding]
version = 1
plan_build_enabled = true
code_intelligence_enabled = true
git_guard_enabled = true
verification_enabled = true
plan_ttl_seconds = 86400

[code_intelligence]
backend = "lexical"
cache_enabled = true
max_files = 20000
max_file_bytes = 2000000

[git_guard]
protect_initial_dirty = true
require_read_before_write = true

[verification]
permission = "ask" # ask / auto / deny
timeout_seconds = 300
max_output_chars = 16000
repeat = 1
# 自定义项必须是 argv 数组；拒绝 shell wrapper、换行与 NUL。
# commands = [["python", "-m", "compileall", "src"]]
```

## 2. Plan 与 Build

```bash
deity plan 分析并规划这次修改 --workspace /path/to/repo --config /path/to/config.toml
deity plans list --db /path/to/deity.db
deity plans show <plan-id> --db /path/to/deity.db
deity build --plan <plan-id> --workspace /path/to/repo --config /path/to/config.toml
```

Plan 只开放读取、搜索、Git 只读、Code Intelligence、Skill 读取与 `submit_plan`，拒绝写入、删除、Shell 和未知效果 MCP。`deity plan` 展示计划后询问一次；同意即进入 Build，拒绝则保留草案供日后查看。单独执行 `build --plan` 也会展示并询问一次。系统校验计划 hash、TTL 与工作区快照，并创建新的 Build Run；不会把原 Plan Run 原地提权。

确认计划后，Build 对计划列出的文件写入不再逐次询问；计划外路径由 Git Guard 拒绝。Shell 仍遵循独立的 `[permission] shell` 策略。Build 默认保护启动时已有改动，目标文件处于 dirty 状态时需逐路径使用 `--allow-dirty <path>`。系统不自动 stash、commit、reset 或 clean；写入需要 read-before-write 和 preimage 一致，补丁冲突不会覆盖用户内容。

## 3. Code Intelligence

```bash
deity code symbol MyType --workspace /path/to/repo
deity code references MyType --workspace /path/to/repo
```

V0.5 使用 Python/Java/TypeScript/TSX lexical backend。结果是 definition candidate 或 textual reference，不等同于 IDE/LSP 级语义证明。索引缓存位于 XDG cache，不写入项目工作区；缓存按工作区、backend、路径、mtime、size 与内容 hash 失效。

## 4. Verification

```bash
deity verify --show-plan --workspace /path/to/repo --config /path/to/config.toml
deity verify --workspace /path/to/repo --config /path/to/config.toml
deity verify --run <run-id> --workspace /path/to/repo --config /path/to/config.toml
```

探测器只从已有 lockfile、构建 wrapper、package scripts 和显式 argv 配置生成命令，不安装依赖。`--run` 把新验证事实关联到已有 Run；每次执行仍受 `ask/auto/deny`、固定 argv、超时、输出上限和取消清理约束。

- `PASSED`：所有必需检查实际退出码为 0。
- `FAILED`：至少一项必需检查实际失败。
- `NOT_RUN`：没有检查或权限拒绝等原因导致未执行。
- `INCONCLUSIVE`：缺依赖、超时、抖动或中断，无法得出通过结论。

## 5. 存储、迁移与回退

首次打开 v3 数据库时，系统先生成并验证同目录 `.v3.bak`，再事务迁移到 SQLite v4。v4 增加 workspace snapshot、plan/build、change set/file change 和 verification 表；旧事件保持只读兼容。

回退步骤：停止 Deity，保留当前 v4 数据库作为审计副本，使用已验证的 `.v3.bak` 恢复旧版本，并关闭 `[coding]` 下全部 V0.5 开关。不要在运行中覆盖数据库；生产或共享数据库操作必须另行审批。
