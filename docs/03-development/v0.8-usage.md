# V0.8 使用说明：统一客户端协议、TUI、配置与 doctor

> 状态：V0.8 候选实现。CLI 与 TUI 共用 `ClientService`（`start_run/subscribe_events/approve/cancel/resume`）与同一 Run 状态和证据；事件以 `schema_version=1` 持久化于 SQLite，可快照 + 增量重放。

## 配置优先级

`CLI > project > user > default`，整段高优先级胜出：

| 层 | 位置 |
|---|---|
| CLI | `deity run/tui/doctor` 的 `--config`（作为 user 层路径）与代码内 CLI 覆盖 |
| project | `<workspace>/.deity/config.toml` |
| user | `~/.config/deity/config.toml` |
| default | 内置默认值 |

`doctor` 报告的 `config` 检查会注明每段的来源，例如 `tui: project；model: user`。

新增配置段（`version = 1`）：

```toml
version = 1

[tui]
enabled = false          # 默认关闭；true 才允许 deity tui 启动
max_events_buffer = 1000 # 订阅队列上限，10–100000

[doctor]
check_docker = false     # 默认不检查 Docker
```

未知段或无效值会报错，且错误信息不含密钥。

## TUI

```bash
uv sync --extra tui        # 安装 Textual（可选 extra，不进主依赖）
deity tui                  # 需 [tui] enabled = true；否则退出码 2
```

键位：`q` 退出、`a` 批准首个待决审批、`d` 拒绝、`c` 取消当前 Run、`r` 恢复当前/指定 Run。`deity tui --task "任务"` 启动新 Run，`deity tui --run-id <id>` 接入已有 Run；事件经 ClientService 订阅喂入 TUI。TUI 只展示审批的工具名与参数摘要，不显示文件内容全文与密钥。未安装 Textual 时 `deity tui` 退出码 2 并提示安装方式，不 traceback；CLI 其余命令正常使用。

回退：关闭 `[tui].enabled` 即回纯 CLI；删 extra 与 `src/deity/interfaces/tui/` 即可移除 TUI。

## doctor

```bash
deity doctor --workspace /path/to/repo [--config /path/to/config.toml]
```

真实检查（示例输出）：

```text
python: ok Python 3.12
dependencies: ok typer/rich/pydantic/aiosqlite/mcp
sqlite: ok 工作区可写 SQLite
git: ok git version 2.43.0
rg: warn 未找到 rg，不阻断
model: warn DEEPSEEK_API_KEY 未设置
docker: ok 未启用检查（Docker 未启用）
config: ok 配置有效（tui: project）
```

有 `fail` 时退出码为 1，否则为 0。模型凭据只检查环境变量名是否存在，绝不读值、不打印值；所有输出经 `Redactor` 脱敏（`api_key/token/secret/password` 键值与 `sk-`、`ghp_` 等模式替换为 `***`）。`rg` 缺失为 `warn`；Docker 只在 `[doctor] check_docker = true` 或沙箱启用时检查，失败时沙箱启用为 `fail`、否则为 `warn`。

## 事件订阅与重连

事件按 `seq` 单调递增；订阅先给快照再跟随增量。断线后用 `after_seq` 续订，不重复执行工具；乱序事件不应用；同一 `approval_id` 重复决定返回首次结果；慢消费者（队列满）会断开订阅并报错，不丢事件后静默续跑。
