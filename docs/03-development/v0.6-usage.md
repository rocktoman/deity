# V0.6 执行沙箱使用与回退

## 启用

默认 `[sandbox].enabled = false`，旧 Shell 和 Verification 使用宿主 Local 执行；Local 的路径检查不提供操作系统隔离。启用 Docker 前，先准备可信镜像，并用 `docker image inspect <ref> --format '{{.Id}}'` 取得本地 image ID。运行时不自动拉取镜像。

```toml
[sandbox]
version = 1
enabled = true
backend = "docker"
required = true
image = "sha256:<64 位本地 image ID>"
workspace_mode = "copy"
artifact_policy = "discard"
network = "none"
read_only_rootfs = true
non_root = true
cpu_count = 1.0
memory_mb = 1024
pids_limit = 128
tmpfs_mb = 256
timeout_seconds = 300
cleanup_timeout_seconds = 15
max_output_chars = 16000
max_workspace_files = 50000
max_workspace_bytes = 1073741824
max_artifact_files = 200
max_artifact_bytes = 52428800
# exclude = ["*.log", "build"]
```

`required = true` 只允许 Docker。Docker CLI、daemon、镜像或必需能力不可用时拒绝执行，不退回 Local。镜像引用允许固定的 `name@sha256:...` 或本地 image ID；运行时 `--pull=never`。仅支持本机 Unix socket Docker context。容器默认禁网、非 root、只读根文件系统、无额外 Linux capabilities，设置 CPU、内存、PID、tmpfs、时限及输出上限。Docker daemon、宿主内核与所选镜像仍属于信任前提。

需要具名网络时，将名称加入 `allowed_networks` 并设置 `network`；Agent Shell 执行前仍需针对 `sandbox_network` 单独审批。`host`、`bridge` 和 `default` 网络始终拒绝。Verification 与独立 `sandbox run` 当前只支持禁网执行。

`env_names` 默认空；仅列出的宿主变量名传入容器，缺失变量使预检失败。变量值不出现在 Docker CLI 参数、配置指纹或审计规格中，直接出现在命令输出时会以 `[redacted]` 替换。显式传入秘密后，容器进程本身仍可读取该值，应只对可信命令使用。

## 命令

```bash
deity sandbox doctor --workspace /path/to/repo --config /path/to/config.toml
deity sandbox run --workspace /path/to/repo --config /path/to/config.toml --db /path/to/deity.db -- cat README.md
```

`doctor` 不运行用户命令，也不拉取镜像；带配置时检查镜像在本地是否可用。`sandbox run` 执行一次明确 argv，工件默认丢弃。常规 Agent Shell 仍经过 schema、权限、审批和工具审计；Verification 保留固定 argv 授权与真实退出码。`artifact_policy = "review"` 只对成功的 Agent Shell 结果逐文件尝试回传，仍需 workspace write 权限、Plan target、初始 dirty 文件授权及 preimage 校验。拒绝项不会覆盖宿主文件；多文件结果可能为 `partial`，不能按原子事务理解。Verification 始终丢弃工件。

工作区复制到 Deity 管理的临时 staging，默认排除 `.git`、`.deity`、`.env*` 与 `.ssh`，拒绝符号链接、特殊文件和硬链接。超限或复制时内容变化则拒绝启动容器。工件由宿主扫描 staging 差异生成，不信任容器内清单。当前只回传有界 UTF-8 文本，二进制、链接及越界路径拒绝。

## 诊断与回退

`sandbox_executions`、`artifact_manifests`、`sandbox_artifacts`、`sandbox_cleanups` 与版本化事件分别记录 intent、结果、工件和清理。清理失败、未知副作用、孤儿容器需要按 execution ID 人工协调；不要自动重试命令或批量清理其他容器。

1. 将 `[sandbox].enabled` 改为 `false`，停止发起新沙箱执行；保存配置、数据库和事件副本。
2. 查询 `sandbox_executions` 中 `prepared/created/unknown` 以及 `sandbox_cleanups` 非 `cleaned` 的 execution ID，结合 `deity.execution=<execution_id>` label 核对精确容器。仅在确认所属关系后，逐个处理容器和 staging。
3. v4→v5 迁移前的 `.v4.bak` 是旧版本回退源。停止 Deity 后，在隔离路径复制该备份，执行 `PRAGMA integrity_check` 和 schema version 检查；保留原 v5 库供只读审计，不做删表逆迁移。
4. 记录仍未协调的 execution、artifact 和 cleanup 为 `UNKNOWN`。关闭开关本身不消除未知副作用。

## 验证

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src
uv run --locked pytest -q
uv run --locked python -m evals.runners.sandbox --require-docker
```

普通 CI 运行无 Docker 的 Fake/Local 场景，Linux Docker 专用 job 构建仓库内固定基础镜像并设置 `DEITY_REQUIRE_DOCKER=1`，缺镜像或 daemon 时失败。`evals/reports/S*.json` 记录每例真实执行状态；`NOT_RUN` 不能写成通过。真实模型、远程 CI 与其他平台需单独记录实际结果。
