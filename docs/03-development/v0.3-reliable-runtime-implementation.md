# Deity V0.3 Reliable Agent Runtime 实施文档

> 状态：实施计划，尚未编码或通过 V0.3 验收。架构基线：[V0.2](../02-architecture/deity-harness-v0.2.md)；需求草案：[V0.3 设计](../05-roadmap/deity-v0.3-design.md)；新决策：[ADR-007](../02-architecture/adr-007-v0.3-reliable-resume.md)。

## 1. 目标、基线与先决条件

V0.3 使本地 CLI 的长任务在上下文增长、进程中断、模型暂时失败及取消时保持可审计、可安全继续。保持 `interfaces → application → core ports ← adapters`，不引入 LangChain、LangGraph、Deep Agents Runtime、HTTP 服务或分布式队列。恢复必须由用户显式发起；任何结果未知的副作用不得自动重放。

| 现状（V0.1/V0.2 代码） | V0.3 必须补足 |
|---|---|
| `ContextBuilder` 仅按字符截断工具输出，`AgentLoop` 消息只在内存 | 预算估算、稳定消息序列、可重建的压缩投影 |
| `RunService` 每次新建 Task/Run，结束后才追加 user/assistant 消息 | 模型响应和工具可见结果逐步持久化；显式 resume |
| `AgentLoop` 的单实例锁、固定三次模型重试 | 跨进程所有权、按错误分类和预算重试、取消作用域 |
| SQLite v1 的 `pending` 占位与结果元数据 | 完整且已脱敏的模型可见 outcome、Checkpoint、租约和 lineage |
| `open()` 把所有 running/approval Run 直接标 interrupted | 先核实 owner/租约，避免第二个进程误伤活跃 Run |

编码前先为协议、数据库迁移、默认预算和取消行为写失败测试。每阶段保留 V0.1 的 L0/L1/L2 与 E01–E08 回归；新能力默认通过配置开关启用。**不要把文档目标写成已达标结果。**

## 2. 固定术语与不变量

- **安全边界**：完整模型响应及其整批工具调用都有已提交的结果、没有待决审批或 `unknown`、模型可见消息能完整重建的时刻。第一次模型调用前也可建立初始边界。
- **intent**：调用外部工具前提交的唯一 `(run_id, call_id)` 记录，含工具名、参数摘要、风险级别、owner epoch；提交失败不得执行工具。
- **outcome**：工具结果、脱敏且有长度上限的模型可见内容、事件和消息在同一事务中提交。提交结果不明时先按 `call_id` 查询。
- **Checkpoint**：安全边界的不可变快照，包括上下文投影、预算累计值、最后事件序号和校验 hash。它不授权操作，也不包含可自动执行的命令。
- **继续**：给同一 Task 创建 `parent_run_id` 指向旧 Run 的新 Run；旧 Run 的 `interrupted/failed/cancelled/completed` 状态不变。默认只允许从 `interrupted` 继续；其他终态需新任务或显式的新尝试接口。
- 每个 Run 只有一个执行 owner；同一 Run 的 `call_id` 唯一。事件在事务提交后发布；终态不得返回 `running`。未知外部副作用永远不计为成功或已取消成功。

## 3. 上下文预算与压缩算法

### 3.1 预算契约

`ContextBudget(model_window, reserved_output, safety_margin, system_tokens, tool_schema_tokens)` 必须使用显式配置或可信的模型能力声明。`model_window` 未知时禁用自动压缩并给出 `context_window_unknown`，不猜测无限窗口。默认软阈值 `0.75 × model_window`、硬阈值 `0.90 × model_window`；实际输入上限为 `model_window - reserved_output - safety_margin`，并取其与硬阈值的较小值。配置验证要求三者均为正且 `reserved_output + safety_margin < model_window`。

`TokenEstimator` 为 Core Protocol；首版保守估算 `max(ceil(UTF-8 bytes/3), ceil(Unicode 字符数/2)) + 每消息固定协议开销 + 工具 schema 开销`。这是**预检估计**，不是厂商精确 token。记录估算器版本与供应商实际 usage；若实际拒绝上下文过长，仅允许一次更严格的裁剪后重试，仍失败则 `context_overflow`。不得把未知 usage 写成 0。估算常数由 fixture 基线校准，变动需 ADR。

### 3.2 分层算法（无模型生成摘要）

1. 从已提交的消息和事件构造规范化序列，确认无半个工具批次。固定保留 system 策略、适用的项目说明、全部尚有效的用户目标/约束、最近 **4 个完整模型轮次**、最新工具结果、待决审批及所有 `unknown` 警示。项目说明属于低信任上下文，不改变权限。
2. 对旧工具输出先做脱敏、按字节上限截断并保留头尾片段；大正文存为受控 `ArtifactRef(id, sha256, byte_count, truncated)`，模型输入注明截断和可重新读取方式。原始审计事实保持可查询，但不得持久化未脱敏秘密。
3. 若仍超软阈值，把更早的完整轮次替换成**确定性结构化账本**：原始消息/事件 ID 范围、任务目标与用户约束的原文引用、已修改文件及已知 hash、工具成功/失败、未解决问题、验证证据 ID、剩余待办（未完成用户目标和未解决失败）、审批与未知状态。只从有类型的持久化事实提取，不推断模型意图或编造测试结果。
4. 对账本做稳定排序与去重；连续压缩时合并引用和事实，不对已有摘要再次做自然语言摘要。使用规范 JSON 序列化计算 SHA-256；校验引用、`call_id`、证据和必保留字段后才写入新投影。旧消息及旧 Checkpoint 不删除。
5. 若必保留部分已超过输入上限，返回 `context_budget_exceeded`，指出占用来源并要求用户缩小目标或提高已确认的窗口；不得静默丢弃约束、审批、失败或证据。

压缩仅在**模型调用前且处于安全边界**执行；压缩结果与 `ContextCompacted(from_message_seq, to_message_seq, old_estimate, new_estimate, estimator_version, summary_hash, artifact_refs)` 同事务提交。快照 hash 不匹配、引用缺失或敏感字段检查失败时丢弃新投影并保留原始上下文。

### 3.3 测试

纯函数单测固定输入检查顺序、阈值、Unicode/JSON/工具 schema 开销、两次压缩幂等性及原始约束逐字保留。属性测试或生成样本覆盖 100+ 轮次、超长输出和窗口缩小。注入摘要校验失败、artifact 缺失、存储回滚、秘密标记字符串；断言模型从未收到不完整工具批次或泄漏值。实际厂商 token 只用于校准报告，不当作确定性单测门禁。

## 4. Checkpoint 与任务恢复协议

### 4.1 持久化格式与事务

SQLite 新增版本迁移（建议 schema v2；最终版本号以迁移链为准），保留旧表数据和 v1 事件读能力：

| 记录 | 最少字段/约束 |
|---|---|
| `run_leases` | `run_id` 唯一、`owner_id`、`epoch`、`expires_at_utc`、`heartbeat_at_utc`；以事务 CAS 续约/交接 |
| `run_lineage` | `new_run_id` 唯一、`parent_run_id`、`source_checkpoint_id`、`decision`、`created_at` |
| `context_messages` | `run_id`、单调 `seq`、`role`、完整脱敏 `payload_json`、`source_event_seq`、`payload_version`；`UNIQUE(run_id,seq)` |
| `checkpoints` | `id`、`run_id`、递增 `version`、`last_event_seq`、`last_message_seq`、`snapshot_json`、`sha256`、`created_at`；`UNIQUE(run_id,version)` |
| `tool_executions` 增量 | `effect_class`、`owner_epoch`、`intent_at`、`outcome_at`、`outcome_json`、`status=unknown` 支持；旧 `result_json` 保持只读兼容 |

完整模型响应与工具批次元数据须先落库，之后才能声明工具 intent。每个 intent、outcome、Checkpoint 都在各自事务中连同事件/消息提交；初始状态及每次完整模型轮次/整批工具结果后的安全边界都必须建 Checkpoint。事务以 `BEGIN IMMEDIATE` 分配连续事件序号，提交后发布事件；外部工具动作绝不置于 SQLite 事务内。Checkpoint 记录 `schema_version`、规范 JSON hash、配置 hash、工作区真实路径与 Git HEAD/状态摘要、累计 turns/tool calls/耗时/已知 token、审批状态及上下文投影。重建时逐项校验版本、hash、事件游标和消息引用；损坏时退回上一个有效 Checkpoint，并仅重放**已提交的记录**，不能重放工具动作。若无法恢复到完整安全边界，返回 `manual_review`。

迁移执行前备份数据库，验证备份可打开与 v1 查询；迁移在事务内完成，失败回滚。为旧历史 Run 提供只读查看；旧 Run 缺少完整 outcome 或上下文时 `resume` 返回 `unsupported_legacy_checkpoint`，不得凭 v1 元数据拼造恢复消息。

### 4.2 所有权与启动恢复

Application 生成不可复用的 `owner_id`，SQLite 事务分配递增 `epoch`。运行中定期续租（建议 5 秒心跳、30 秒租期；用可注入时钟测试）；每次模型/工具派发和状态写入前校验 epoch。租约到期只表示需要核查：在本机检查 owner 进程身份与启动标识，仍存活则拒绝接管；无法确认其死亡或受控子进程状态时进入 `manual_review`。旧 epoch 的提交被拒绝，且不得把旧 owner 的晚到完成事件发布为新 Run 事实。

启动扫描仅处理**确认没有活跃 owner** 的遗留 Run：事务内标记 `interrupted` 并记录 `RunInterrupted`。原 `waiting_approval` 不自动批准；审批决定不跨 Run 继承。多进程同时启动时只有一个扫描者能完成状态迁移。

### 4.3 `deity resume` 判定与用户流程

1. `deity runs inspect <run_id>` 展示最后有效 Checkpoint、未决工具、工作区/Git 变化和预算余额；输出脱敏。
2. `deity resume <run_id>` 先计算 `RecoveryDecision = resume | manual_review | abort`。`resume` 仅适用于旧 Run 为 `interrupted`、owner 已停止、Checkpoint 完整、无 pending/unknown/审批、工作区路径一致且相关文件 hash 未漂移、预算仍足够的情况。
3. `manual_review` 列出具体 `call_id`、工具、时间、风险、可查询证据。用户可确认“已执行且提供证据”或“未执行”；系统只记录核对事实，不自动重试旧 `call_id`。V0.3 的人工核对不把该旧 Run 转成 `resume`：用户可从旧安全边界开启**新任务**并明确新的操作范围；证据不足的写/Shell 继续标 `unknown`，不能声称是无缝恢复。
4. `abort` 用于损坏且无有效边界、权限/工作区不匹配、预算耗尽或旧版数据不足。创建新 Run 时复制已确认历史投影，写 `RunResumedFrom` 与 lineage；剩余预算按 Task 累计用量扣减，不因重启清零。新 Run 用新 `call_id`；旧 Run 保持 `interrupted`。

模型请求已经发出但无完整响应时，旧请求的费用可能未知；恢复记录 `usage=unknown`。显式继续可重新请求模型，但 UI 必须提示可能重复计费。任何已派发工具而 outcome 未确认的情况不得进入自动安全路径。

## 5. 错误重试策略与预算

`RetryPolicy` 由 Core 决定，Provider 仅返回规范化错误与可选 `Retry-After`；关闭官方 SDK 的隐式重试，避免双层重试。默认模型最多 **3 次总尝试**（初次 + 2 次重试），指数退避 `0.5s, 1s`，每次加 `0–20%` 可注入抖动；`Retry-After` 优先，但不得超过本轮和 Task 剩余 deadline。等待可取消。

| 错误/阶段 | 策略 |
|---|---|
| 429、明确临时 5xx、连接建立前失败 | 仅在没有已提交模型响应、没有语义流片段/工具 intent、预算足够时重试 |
| 流已输出文本或工具 JSON 片段后断开 | 标记本次 attempt 不完整并失败；不自动重发或执行任何工具 |
| 401/403、400/422、未知模型、协议不完整、无效工具 JSON | 不做同请求重试；错误分类记录，按既有工具纠错契约处理 |
| 只读工具瞬时 I/O 失败 | 仅显式标记 `read_only` 且尚无结果时至多 1 次；新 attempt 有独立审计 |
| 写文件、补丁、Shell、Git 及未知副作用 | 不自动重试；先按 intent/outcome 与文件/Git 证据核对 |
| SQLite busy/提交响应丢失 | 事务级有界重试；提交是否成功不明时按稳定操作 ID 查询，绝不因此重复外部工具 |
| 取消、deadline、预算耗尽 | 立即停止重试并落相应终态 |

`RunBudget` 至少跟踪 Task 跨 Run 累计的 turns、tool calls、活跃执行耗时和已知 provider tokens；单 Run deadline 使用 monotonic 时钟，恢复后剩余 Task 预算不重置。价格缺失或 usage 缺失时费用标 `unknown`，不得用 0 通过成本门禁；若启用硬费用上限但无法可靠计量，拒绝执行或要求改用可计量配置。每个 attempt 记录 `attempt_id`、错误码、是否已有语义输出、退避时长及停止原因。

## 6. 取消传播与终态提交

`RunService.cancel(run_id)` 设置可重复调用的 `CancellationScope`；CLI 第一次 Ctrl+C 调用该 API 并等待清理。Core 在模型请求前、流事件间、审批等待中、退避等待中、每个工具派发前及 Checkpoint 前检查取消。模型适配器在 `finally` 关闭 SDK stream；审批 broker 立即返回取消；LocalExecutor 对受控 Shell 进程组先 TERM，宽限 **2 秒**，仍存活再 KILL 并回收，输出上限继续生效。Windows 进程树清理需独立平台实现和测试；没有实现前不宣称支持该平台的强清理。

取消与自然完成/超时竞争时使用单一事务 CAS 写终态，只有获胜路径发布终态事件。若工具已派发但结果不可知，先记录 `unknown` 和审计，再将 Run 置 `cancelled`；报告不得写“工具未执行”。取消请求在持久化临界区到来时，给最终审计提交一个有限清理窗口（建议 5 秒）；提交失败则保留 `interrupted`/待核查事实，不能仅凭内存状态宣称取消成功。第二次 Ctrl+C 允许 CLI 强制退出，但下一次启动必须进行 owner 与 unknown 核查。

## 7. 实施顺序与文件边界

| 阶段 | 先写失败测试 | 最小实现与预计文件 | 退出门禁 |
|---|---|---|---|
| S0 基线 | 复跑现有 63 项测试和 E01–E08；建立旧 DB fixture | ADR-007、配置和事件版本清单 | 记录实际基线、旧数据可读；失败先修复 |
| S1 持久化事实 | 模型响应/工具 outcome 事务、崩溃点、脱敏、旧版兼容 | `core/contracts`、`adapters/storage`、`application/run_service.py`，迁移 v2 | 断电点无伪完成，外部动作最多派发一次；消息可重建 |
| S2 压缩与 Checkpoint | 预算、保留字段、连续压缩、hash/回滚 | `core/context`、`core/runtime`、storage Checkpoint 端口 | 100 轮确定性压缩；无约束/证据丢失 |
| S3 恢复与所有权 | 双进程竞争、租约过期、unknown、工作区漂移 | `core/state`、`application`、`adapters/storage`、CLI `resume/inspect` | 原 Run 不复活；不自动重放未知副作用 |
| S4 重试/取消 | 429/401/断流、Ctrl+C 各阻塞点、子进程树 | `core/runtime`、两种模型适配器、tools/execution、CLI | 有界重试、取消终态唯一、受控进程收敛 |
| S5 长任务评估 | 故障注入 runner、100+ 步、报告误判测试 | `tests/{unit,integration,e2e}`、`evals/cases`、`evals/runners` | 第 8 节全部门禁与回归通过 |

每个阶段依次执行“失败测试 → 最小实现 → 对应集成/故障注入 → 全量回归”；前一阶段门禁未通过不得推进下一阶段。S1 先于 S2，是因为现有 v1 存储不足以恢复完整模型可见结果。CLI 不直接操作 SQLite 或执行工具；Core 不导入 SDK、SQLite 或 Typer。架构性改动更新本 ADR、V0.3 设计及架构文档的版本说明。

## 8. 长任务可靠性测试标准

### 8.1 隔离与可重复性

L0 使用 FakeModel/FakeTool 和虚拟时钟，完全无网络；L1 使用临时 SQLite、临时 Git 工作区和真实受控子进程；L2 使用 scripted model 运行 E01–E08 及新增 R01–R06。每次测试新建 fixture 仓库和数据库，固定随机种子、配置、超时和预算，保存机器可读 JSON/Markdown 报告。L3 真实模型仅在配置密钥与预算后单独运行，记录波动和费用未知项，不作为确定性 CI 断言。

| 用例 | 注入/负载 | 必须通过的机器断言 |
|---|---|---|
| R01 长上下文 | ≥100 个完整轮次、≥20 次压缩、两种工具输出大小 | `turns≤budget`、输入估计≤上限、用户约束/证据引用/unknown 全保留、摘要 hash 可复算 |
| R02 崩溃矩阵 | intent 前、intent 后、外部执行后未记 outcome、outcome 提交后、Checkpoint 提交前、Checkpoint 提交后，逐点杀独立 worker | 每点状态可解释；未知副作用自动重放次数 **0**；已提交事件序号连续；无假完成 |
| R03 owner 竞争 | 两个进程同时启动/续租/恢复，旧 epoch 晚到提交 | 任一时刻最多 1 个可派发 owner；旧 epoch 不能提交；活 owner 不被启动扫描误标 interrupted |
| R04 取消矩阵 | 模型流、退避、审批、工具排队、Shell 进程组、终态竞态各点取消 | 终态事件恰好 1 条；取消确认后无新工具派发；Linux/macOS CI 中模型/审批等待≤2s、受控 Shell≤5s 收敛 |
| R05 错误矩阵 | 429+Retry-After、临时 5xx、401/403、断流半包、SQLite busy/提交不明、磁盘满 | 尝试次数≤3；认证不重试；无部分工具执行；提交不明先查询；事务回滚不发布完成事件 |
| R06 恢复完整性 | 旧 v1 DB、损坏最新快照、工作区/Git 漂移、预算耗尽、秘密标记注入 | 旧数据可查询；损坏回退或 manual_review；漂移/预算拒绝；密钥不进入 DB/日志/报告 |

所有安全断言 **100% 通过** 才能合并。取消时延是初始 CI 目标，在 Linux/macOS runner 用 monotonic 测量并记录 P50/P95/最大值；环境抖动导致时延失败时保留原始结果，不放宽安全断言。长任务压缩前后分别运行相同 scripted fixture，比较功能断言、tool calls、事件数、峰值估算 token、耗时和 SQLite 大小；首轮只建立实测基线，性能回归阈值经 ADR 校准后才写入 CI。每个恢复判定附 `run_id`、Checkpoint ID、事件序号、配置 hash、错误码和证据 ID；报告中 `PASS/FAIL/NOT_RUN/UNKNOWN` 必须分明。

## 9. 验收命令、发布与回退

实施时逐阶段实际运行并记录退出码：

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest -q tests/unit tests/integration tests/e2e
uv run python -m evals.runners.runner
```

新增 R01–R06 runner 命令在 S5 编码时写入 `pyproject.toml` 与 CI；本计划不把尚不存在的命令写成已执行。候选版本必须提供数据库备份/恢复演练、v1→v2 迁移报告、两种模型适配器的本地协议测试、CLI 中断/继续演示以及完整故障注入报告。回退时关闭 `context_compaction` 与 `resume` 开关，使用已备份的 v1 数据或保持 v2 只读；**不执行逆向删表迁移，也不重放工具**。任何重复副作用、越界、秘密泄漏或错误终态均阻断发布。
