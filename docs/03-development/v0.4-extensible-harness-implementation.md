# Deity V0.4 Extensible Harness 实施文档

> 状态：实施计划，**NOT_RUN / 未实现**。需求依据：[V0.4 设计](../05-roadmap/deity-v0.4-design.md)；运行时基线：[V0.3 实施文档](v0.3-reliable-runtime-implementation.md)、[ADR-007](../02-architecture/adr-007-v0.3-reliable-resume.md)。本文件中的命令、用例和阈值是待执行门禁，不是验收结果。

## 1. 目标、基线和边界

V0.4 在现有 CLI、Agent Loop、SQLite v2、Checkpoint 和单 Run 所有权上接入本地 stdio MCP、Skills、Hooks。扩展必须经 Application/Core 端口和现有 Tool Runtime，不改变已提交 Run 事实，也不让外部文本获得授权能力。HTTP/OAuth MCP、远程插件分发、自动运行 Skill 脚本、Multi-Agent、TUI 和 Docker 均不在本版。

仓库现状：`LocalToolDispatcher` 在 `adapters/tools/__init__.py` 用 `TOOL_ARGS` 固定内置工具；`RunService._authorize()` 将非 Shell 工具归入 `workspace_write`；`Config` 只识别 `run/permission/model`；`AgentLoop` 通过 `ToolDispatcher`、`SessionRepository` 和 `ModelProvider` 运行。因此不能把 MCP 工具直接塞入现有名称表，也不能让其继承本机 `auto` 写权限。当前 V0.3 回归、E01–E08、R01–R06 和历史 L3 结果只作为参照；实施开始时重新记录本地基线。历史 L3 4/4 不代表 V0.4 已通过。

设计文档说“不改 Core”，同时要求在 Core 增加契约和 Hook 决策。实施解释为**不破坏现有 Core 对外行为与依赖方向**；允许增加协议、类型和注入点。若需要改变 `ToolDispatcher` 兼容语义、Run 状态、事件/配置/SQLite 格式，先提交 ADR、版本与迁移方案，再编码。S1–S4 是交付顺序，不应为了顺序制造无关的代码依赖。

## 2. 先决决策与通用契约（S0）

先写 V0.4 ADR，至少冻结以下内容，再写失败测试：

| 决策 | 最小契约与默认值 | 必测风险 |
|---|---|---|
| 扩展身份 | `ExtensionId(kind, source, name, version)` 与稳定、可审计的 `schema_version`；配置中的 server/Skill/Hook ID 不因展示名变化而漂移 | 同名覆盖、版本变化、旧配置读取 |
| MCP 工具 | `mcp:<server>:<tool>`；注册时拒绝非法/重复 ID、过大 schema、无法映射的参数 schema；工具描述作为不可信模型上下文 | 名称冲突、描述注入、参数片段执行 |
| 效果与授权 | 外部工具默认 `unknown_effect`，默认 **ask**；配置的能力声明不能自证只读。服务端、工具、参数共同形成授权摘要，授权只对当前完整调用有效；用户现有 `auto` 不扩大到 MCP | “只读”伪装、参数更换、审批复用 |
| 生命周期 | server 启动命令与允许环境变量由用户配置；启动即本机进程动作，首次启用需明确批准。固定启动/握手/调用/关闭超时、输出上限、并发上限；异常进入明确错误态 | 僵尸进程、stdout 污染、断线重连重复副作用 |
| 持久化 | MCP 调用沿用 `(run_id, call_id)` intent/outcome、epoch、事件序号和 unknown 规则；Skill 激活与 Hook 决策事件有版本、来源、摘要、时间和脱敏结果 | 崩溃后重放、伪完成、秘密写入事件 |
| 关闭与恢复 | `mcp/skills/hooks` 各有配置开关，默认关闭；关闭后旧 Run/事件可读。影响上下文或策略的版本/配置摘要进入恢复预检；漂移时拒绝无声续跑 | Checkpoint 上下文变化、旧版降级 |

每一新依赖先记录用途、替代方案、许可证、锁定版本、维护/安全风险和移除成本。本版只在 S1 增加所需的 MCP Python SDK；Skill frontmatter 优先复用现有依赖或标准库，确有解析需求再论证。扩展配置不含凭证值，只允许引用环境变量名；事件、报告及模型上下文不得泄漏密钥。

交付文件建议：`docs/02-architecture/adr-010-v0.4-extensions.md`、`core/contracts` 中扩展 DTO/Protocol、`application/config.py` 中版本化配置、测试 fixture。具体文件名可随现有模块组织调整，但依赖方向不得变。

## 3. S1 — 本地 stdio MCP Client

1. **先写失败测试。** Fake server 模拟 initialize、能力协商、`tools/list`、`tools/call`、断线、超时和协议污染；Fake Tool Runtime 断言参数校验、权限和审计顺序。
2. 在 `adapters/mcp/` 封装 SDK 会话和 stdio 子进程；`McpServerConfig` 限制可执行文件、参数、工作目录、环境白名单、启动/调用超时及最大工具数。只将协商成功且 schema 有界的工具暴露给模型；server 重启后重新校验能力与 schema，不悄悄替换运行中的工具定义。
3. 用统一注册/分发端口把外部工具接到 Tool Runtime。流程固定为完整参数 → schema → policy → workspace/参数边界 → approval → durable intent → call → durable outcome/audit。对无法证明边界的外部工具按未知副作用处理；工作区路径检查不能限制 server 内部行为，不宣称沙箱。
4. `deity mcp list/test` 由 CLI 调 Application；`list` 显示配置和发现状态，`test` 做握手与 schema 检查，不调用任意业务工具。启动 server 的用户批准与普通工具调用批准分开记录。

**关键测试（L0/L1/L2）：** 两个隔离的本地 server 可同时发现且无重名覆盖；正常只读/写入调用有完整 intent/outcome 和审批证据；无效 JSON、额外字段、超大 schema、工具重名、恶意描述、结果中的 prompt injection 不改变策略；server 启动失败、崩溃、超时、stdout 污染、取消能清理受控进程；调用已发出后断线标 `unknown`，恢复时零自动重放；调用前断线可重新握手但不能复用旧审批或旧 `call_id`。测试 server 无真实网络、无用户项目写入。

## 4. S2 — Skills 渐进加载

1. 先定义 `SkillManifest`、`SkillCatalog`、`SkillLoader` 和激活事件。配置明确用户级/项目级目录与优先级；同 ID 不静默覆盖，展示来源与信任级别。仓库 Skill 和 `AGENTS.md` 只是任务上下文。
2. 发现阶段只读取有界元数据；匹配后才读取 `SKILL.md` 正文；资源仅在明确引用且路径校验后按需读取。大小、数量、递归深度及总上下文预算均设上限。正文和资源视为不可信数据，不能覆盖当前用户任务、系统策略或 Tool Runtime 授权。
3. `deity skills list/inspect` 展示来源、激活状态、解析错误和摘要；`inspect` 不执行脚本。若 Skill 建议执行脚本，仍作为普通 Shell 调用走完整审批链。Skill 激活记录 ID、版本/内容 hash、引用资源和上下文占用，供 Checkpoint/恢复预检。

**关键测试：** 10 个 Skill 的索引只含元数据，命中 1 个时仅该正文进入模型上下文；不命中 0 个正文加载；畸形 frontmatter、重复 ID、循环引用、深层/绝对路径、symlink 越界、文件修改竞态、超大资源均可解释地失败；Skill 含“忽略用户/自动授权/执行脚本”文本时权限不变；取消加载不产生半个激活事件；恢复时内容 hash 漂移有显式判定。用 FakeModel 检查实际送入的消息，而非只检查 loader 返回值。

## 5. S3 — Hooks 决策与观察

1. 冻结 `HookContext`（只读快照）、`HookDecision`（allow/veto + 原因）、`HookFailurePolicy`、稳定排序键和事件版本。V0.4 先支持受信任的本地配置/代码注册；不把任意仓库脚本自动作为 Hook 执行。
2. `BeforeModel`、`BeforeTool`、`AfterTool`、`BeforeFinish` 经 Core 注入点调用。Observer 只能接收不可变事实；Policy Hook 只能 veto，多个 Hook 取最严格决定，任何 Hook 不能把底层 deny 变 allow。`BeforeTool` 在 intent/执行前，`AfterTool` 只观察已持久化 outcome；`BeforeFinish` 不能伪造验证证据。
3. 每次调用有 deadline、取消传播、递归保护和明确失败策略。策略 Hook 异常/超时默认拒绝该动作并审计；Observer 异常隔离并记失败，不吞掉原始 Core 错误。Hook 引起的等待和 veto 不创建虚假成功事件。

**关键测试：** 排序稳定、多个 veto 决议可复算；卡死 Hook 超时、异常、递归调用、取消与终态竞态；observer 尝试改写上下文/结果失败；Hook allow 遇 Tool Runtime deny 仍拒绝；`AfterTool` 中异常不掩盖真实工具失败；持久化失败时不得宣称 Hook/Run 完成。Fake 时钟避免 CI 上依赖真实长等待。

## 6. S4 — 扩展兼容、评估与发布

为第三方作者提供本地示例 server、Skill、Hook 和独立兼容测试套件，明确配置/schema 版本、错误码和升级策略。示例只运行在隔离 fixture 仓库。先测旧配置/旧事件读取和禁用扩展后的 V0.3 路径，再测开启组合：MCP 工具输出触发 Skill 建议、Hook veto 时仍由 Tool Runtime 拒绝且审计链完整。不能因扩展禁用就删掉历史审计事实。

### 6.1 测试覆盖矩阵与断言

| 层级 | 主要用例 | 必须由机器断言的事实 |
|---|---|---|
| L0 单元/协议 | schema 映射、配置拒绝、Skill 匹配/边界、Hook 决议、事件序列化 | 不受信任文本不改变权限；无半包执行；旧配置解析符合版本规则 |
| L1 集成 | 两个 stdio server、CLI list/test、临时 SQLite、取消/崩溃、10 Skill、Hook 注入 | 完整调用才执行；intent 先于副作用；outcome 提交后才报告完成；进程已回收 |
| L2 故障与评估 | MCP 断线矩阵、Skill 注入/路径竞态、Hook 超时/递归、禁用开关、恢复漂移 | `unknown` 自动重放次数为 0；越界/未授权执行次数为 0；终态事件恰好 1 条 |
| L3 真实模型 | 隔离 fixture 的一个发现→调用→汇报任务和一个 Skill 命中任务，人工配置预算/密钥后单独运行 | 文件/事件/审批证据可核验；成本、时延、模型调用数记录；不替代 L0–L2 |

建议新增 X01–X06 固定评估：X01 双 server 正常调用；X02 权限/注入；X03 调用中断与恢复；X04 10 Skill 渐进加载；X05 Hook 决议/故障；X06 全部扩展关闭与旧数据兼容。每例在 `evals/cases/` 写固定输入、隔离 fixture、预期事件和可执行断言，在 `evals/runners/` 产出 JSON/Markdown，状态使用 `PASS/FAIL/NOT_RUN/UNKNOWN`。X03 必须用独立 worker 在 intent 前、intent 后、服务端已执行但 outcome 未提交、outcome 提交后注入退出，检查 SQLite 与 server 端计数，不能只 mock 异常。

### 6.2 阶段退出门禁

| 阶段 | 交付物 | 阻断条件 |
|---|---|---|
| S0 | ADR、契约/配置版本、基线与依赖记录 | 授权/副作用分类未定、既有回归失败未归因 |
| S1 | MCP SDK adapter、CLI、双 server fixture、协议/安全/崩溃测试 | 任一未授权调用、重复副作用、进程泄漏、审计缺口 |
| S2 | Catalog/Loader、CLI、10 Skill fixture、注入/边界测试 | 全量预加载、越界读取、脚本自动执行、用户指令被覆盖 |
| S3 | Hook Registry/注入点、决议事件、故障测试 | 允许绕过权限、异常掩盖事实、终态不一致 |
| S4 | X01–X06 报告、兼容矩阵、演示、回退演练 | 任一安全断言失败，或扩展关闭后 V0.3 回归失败 |

逐阶段执行“失败测试 → 最小实现 → 同层回归 → 下一阶段”。安全断言要求全部通过；性能阈值先记录基线，再由 ADR 校准，不把未经测量的数字写成已达标。

### 6.3 验收命令和证据

实施时运行并记录命令、退出码、平台、Python 版本、commit、配置 hash、报告路径；新增评估 runner 的最终模块名以实际实现为准：

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src
uv run --locked pytest -q
uv run --locked python -m evals.runners.runner
uv run --locked python -m evals.runners.reliability
# S4 实现后：uv run --locked python -m evals.runners.extensions
```

真实模型验收单列运行，不能用历史 L3 结果替代。CI 至少在现有 Ubuntu/macOS × Python 3.12/3.13 矩阵执行确定性门禁；有网络或密钥的真实模型运行不得成为普通 PR 的隐式依赖。

## 7. 回退与数据兼容

功能开关分别关闭 MCP、Skills、Hooks；关闭后 CLI 和 V0.3 基础工具仍可工作，旧扩展事件保持只读。新配置字段采用明确版本和严格校验；不识别的旧/新配置不得静默放宽权限。若改 SQLite schema，迁移前备份、验证可打开，提供 forward migration、旧事件读取和恢复演练；不执行破坏性的逆向删表。扩展版本、Skill 内容或 Hook 策略变化影响 Checkpoint 时，`inspect/resume` 给出具体漂移和人工处理路径，不静默沿用旧审批。发现权限绕过、未知副作用重放或秘密泄漏，立即关闭对应开关并阻断发布。

## 8. 提交与验收记录模板

每阶段提交包含：契约/数据模型、正常/错误/取消测试、权限和恢复回归、可运行演示、执行记录、文档及回退步骤。提交信息使用中文。候选验收记录逐项列出 `PASS/FAIL/NOT_RUN/UNKNOWN`、实测退出码与证据路径；未运行的 L3、平台或故障点明确标 `NOT_RUN`。
