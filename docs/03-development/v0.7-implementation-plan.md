# Deity V0.7 Multi-Agent Runtime 实施计划

> 状态：本地候选实现，远程 CI 与真实模型另行核验。依据：[V0.7 设计](../05-roadmap/deity-v0.7-design.md)。实施基线为 V0.6 本地候选、SQLite v5；实际结果见 [V0.7 候选验收记录](../04-evaluation/v0.7-candidate-2026-11-01.md)。

## 1. 交付范围与前置决策

主交付是**受控的只读委派**：父 Run 可以分配有限任务给子 Run，子 Run 有独立上下文、租约、预算、状态和事件，父级只接收压缩结果及可验证证据。支持多个只读子任务并发、取消级联、部分失败、重启后可审计。默认关闭，关闭时原单 Agent 流程、配置指纹和旧数据读写行为保持一致。

V0.7 设计的 §2.4“并发写入探索”仅做隔离 fixture 中的技术验证和决策记录；不开放可写子 Agent、自动合并或普通 CLI 开关。若要作为发布能力，需另写 ADR、实现计划和验收门禁。不开启 TUI、分布式调度或新模型框架。

编码前先提交 ADR-013，冻结下列问题：

1. **谱系分离**：现有 `run_lineage` 表示 checkpoint 续跑来源；新增委派关系不能复用它的语义。定义 `root_run_id`、`parent_run_id`、`delegation_id`、`depth`，明确续跑后的父子归属与树查询。
2. **预算口径**：父级 `max_turns/max_tool_calls/input_tokens/output_tokens/deadline` 如何对自身与子级统一计费；为子任务原子预留，未用额度可回收，缺失 usage 不可当作零成本。时间上限不得超过父级剩余 deadline。
3. **状态口径**：`partial` 是委派聚合结果，不把既有 Run 终态擅自改写；父 Run 结束前如何处理等待中的子 Run、结果未知和孤儿 Run。
4. **权限口径**：只读 profile 由系统构造，工具集合是父级可用工具的严格子集。Shell、MCP、Hooks、Skills、Verification、Docker 工件回传等可能有副作用的入口默认不暴露；任何例外必须有可执行的只读证明与专项测试。
5. **数据库/事件/配置**：SQLite v5→v6 正向迁移、事件 schema version、旧事件只读、开关和恢复指纹、备份与隔离恢复操作。采用 Python 标准库 `asyncio`，无新增运行依赖。

任何与 V0.2 分层或已采纳 ADR 冲突的方案先停在 ADR 评审，不用实现绕过边界。

## 2. 现有落点与需要补齐的能力

| 现状 | V0.7 增量 |
|---|---|
| `core/runtime/AgentLoop` 是单 Run、串行工具循环 | 保持单 Run 语义；另设委派协调器和调度器，不在 Loop 内直接创建子进程或 SQLite 连接 |
| `application/run_service.py` 组合模型、工具和单个活动 Loop | 增加委派 Application 服务、父子取消登记及子 Run 生命周期；CLI 只调用服务 |
| `core/contracts/__init__.py` 有 `AgentRequest/RunBudget/SessionRepository` | 新增版本化委派 DTO、策略端口、预算账本端口与结果归约端口 |
| `adapters/storage` 已有 SQLite v5 与续跑 `run_lineage` | 新建委派表及事件事务，保留续跑语义；创建前做可验证备份 |
| `application/config.py` 使用严格 TOML 校验 | 新增默认关闭的 `[multi_agent]` 配置、边界校验和启用时指纹 |
| `evals/runners` 有 E/R/X/A/S 固定用例 | 新增 M 系列确定性 fixture 与独立门禁，旧门禁全量回归 |

## 3. 分阶段实施

### S0：基线、ADR 与失败测试

- 阅读本设计、V0.2 架构、ADR-007/011/012、现有 Run/工具/存储/配置/测试；记录 `git status` 和 V0.6 门禁实际结果。不得将上次候选报告当成本次实测。
- 写 ADR-013，列明上节五项决策、数据迁移、回退和安全威胁。冻结默认参数初值，如 `max_children`、`max_depth`、`max_concurrency`、结果字数上限；具体阈值由测试和基线测量校准。
- 先补失败测试：配置默认关闭与非法值、契约校验、同一父级重复 `delegation_id`、预算超额、循环/递归委派、状态终态保护。
- **退出门禁**：ADR 与 V0.7 设计无冲突；旧功能基线可复现；失败测试只因目标能力缺失而失败。

### S1：委派契约、策略和预算账本

- 在 `core/contracts/delegation.py` 定义 `DelegationRequest`（目标、范围、输入引用、工具 allowlist、预算、预期结果、父 Run ID、幂等 ID）、`SubAgentResult`、`AgentTree`、只读 profile、错误分类和版本号。拒绝空目标、越界范围、非法工具与不完整参数。
- 在 `core/delegation/` 实现纯策略：父级权限求交、深度/子数限制、任务合同规范化、预算预留/结算/回收、结果长度限制。所有状态变化由明确事务驱动；并发预留不能只靠进程内锁。
- 在 `application/config.py` 加严格配置，默认关闭；只在启用时把委派策略加入恢复指纹，避免改变旧 Run 指纹。
- **测试**：FakeModel/FakeTool 无网络单测，覆盖成功、拒绝、重复请求、并发超额、usage 缺失、额度回收与截止时间；父预算合计不得被并发子任务突破。
- **退出门禁**：纯 Core 不导入 SDK/SQLite/CLI；配置及契约测试通过，关闭开关旧测试通过。

### S2：SQLite v6 与委派生命周期

- 在 `adapters/storage/schema_v6.py` 和仓库端口新增委派事实：唯一委派 ID、父/子 Run 关系、task contract hash、预留与结算预算、状态、结果与证据引用；索引支持按父、根和子查询。沿用 `runs/events/steps/evidence` 事实，不复制全部日志。
- **原子性**：预留预算、创建子 Run、记录委派 intent 与事件在同一数据库事务；完成/失败/取消/未知时结算并写事件。重复 ID 返回已存事实或拒绝冲突，不新建第二个子 Run。
- 迁移前使用 SQLite backup API 生成并校验 `.v5.bak`；故障注入覆盖中途失败、重复迁移、并发打开、损坏备份拒绝、旧事件读取。重启扫描将失去所有者的活动子 Run 标为 interrupted，未知副作用保持 unknown，不自动重放。
- **退出门禁**：事件顺序、外键、事务、重复 ID、迁移和隔离恢复测试通过；旧 v5 库只读兼容可证明。

### S3：只读子 Agent 垂直闭环

- 在 `application/delegation_service.py` 用现有 `RunService`/`AgentLoop` 和 Repository 端口创建独立子 Run；子上下文仅含 task contract、允许的输入和必要项目指令，不继承父级全部对话、秘密或工具日志。保留 trace lineage。
- 在工具注册/分发层实施**能力 allowlist + 每次调用再校验**；只允许经审计的读取、搜索、代码定位等。`shell` 即使父级可用也拒绝；模型文本、AGENTS.md、Skill 或 MCP 返回值不得扩大授权。工作区边界和 symlink 检查沿用当前管线。
- `ResultReducer` 只回传有长度上限的摘要、状态和已在仓库中存在且属于该子 Run 的 evidence ID；无效引用拒绝或标记 inconclusive。原始日志仍可按 ID 检索，不注入父级模型上下文。
- CLI 提供最小委派入口与树/结果查看，所有逻辑经 Application；默认关闭时显式报功能未启用。
- **测试**：独立上下文、工具越权、Shell 试图写文件、无效证据、超长输出、模型异常、取消、重复调用、真实临时 fixture 工作区前后 hash 不变。
- **退出门禁**：单子任务端到端可用；任何拒绝有审计事件；无工作区写入。

### S4：调度、并发与取消级联

- 在 `core/delegation/scheduler.py` 定义 `AgentScheduler/ConcurrencyLimiter/BudgetAllocator` 端口或纯策略；Application 用 `asyncio.TaskGroup` 管理执行、固定并发槽与有界 FIFO 队列。排队任务也占用已预留预算，取消时释放。
- 父级取消、失败或终止时停止接单，向运行中的子 Loop/模型流/受控工具传播取消，等待有界清理，再落库每个子 Run 的终态；超时或异常时记录 interrupted/unknown 并进入人工协调。子任务失败可聚合为 partial，不掩盖其他成功结果。
- 在进程重启时从持久化委派事实恢复**审计与协调状态**；不自动启动原子任务，也不盲目重放未知调用。
- **测试**：多子任务同时争用最后一个预算槽、并发上限、FIFO 公平性、父子取消竞态、模型流阻塞、工具超时、TaskGroup 异常、进程重启无孤儿 running Run。使用事件/屏障同步，避免靠 sleep 猜测时序。
- **退出门禁**：预算不超、并发有界、取消后无活动子任务、每个子 Run 可追踪。

### S5：评估、文档和发布候选

- 在 `evals/cases/` 与 `evals/runners/multi_agent.py` 增加 M01–M12：协议与幂等、只读工具、Shell 越权、工作区边界、上下文隔离、证据引用、输出截断、预算竞争、并发公平、父取消、子失败 partial、崩溃恢复。每例在临时 fixture 仓库与临时 SQLite 上用机器断言输出事件、文件 hash、状态和预算。
- 更新 `README.md`、V0.2 架构扩展、开发指南、评估计划和 V0.7 使用/回退文档；给出 CLI 示例、配置、证据查看、停用开关与 v6→v5 **隔离路径**恢复流程。
- 运行 `uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy src`、`uv run pytest -q`、E/R/X/A/S/M 固定评估；有 Docker 的专用 S 门禁按现有 `--require-docker` 执行。真实模型、远程 CI 和未运行平台分别标 `NOT_RUN`，不得混入本地通过结论。
- 候选记录列明模型/配置哈希、父子 run_id、事件序列、预算预留与实耗、耗时、工具调用、失败分类、证据和前后文件 hash。安全断言 100% 通过才可候选发布；性能阈值在首轮实测后再通过 ADR 固化。

## 4. 并发写入探索与回退

另设隔离实验：临时 Git fixture 每个子任务独立 worktree，仅验证同文件冲突、测试环境差异、dirty 用户文件保护及 diff review/审批流程。实验不接入默认 CLI，不自动合并，不对用户工作区执行写入。实验结果决定是否另立发布版本与 ADR。

严重越权、预算穿透、未清理子任务、未知副作用重放或用户文件改动，立即关闭 `[multi_agent].enabled` 并阻断发布。关闭开关停止新委派；保留 v6 事实供审计，逐项协调活动子 Run。旧程序若必须读取旧库，先停止进程、备份 v6，在隔离目录验证 `.v5.bak` 后恢复；不对当前库做删表逆迁移。
