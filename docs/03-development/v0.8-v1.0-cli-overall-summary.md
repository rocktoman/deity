## 三、修掉的失败及根本原因

1. **基线 7 个 Anthropic 适配器失败**（`test_model_gateway`、`test_model_adapters`，报错 `InvalidURL: Invalid port`）。
   根因：本机 `NO_PROXY` 同时包含裸写 `::1` 与方括号写 `[::1]`；anthropic 2.3.0 自带的
   `get_environment_proxies()` 是旧版 httpx 逻辑的复刻，缺少方括号 IPv6 分支。已修复，全量通过。
2. **V1.0 开发中修掉的真实问题**（均有回归测试）：存储层 `_redact` 漏脱敏裸 `sk-…` token；
   崩溃恢复漏发 `ToolOutcomeUnknown` 事件；`uv build --locked` 参数不存在；
   旧测试版本号硬编码 `0.1.0`；soak 孤儿进程计数把 `ps` 自身算进去。
3. **最终核实初跑的 4 个失败**（`test_full_extension_cli_walkthrough`、
   `test_plan_show_and_build_cli`、`test_build_can_fill_staged_empty_file`、
   `test_local_backend_declares_no_isolation_and_bounds_cwd`）。
   根因：**不是代码问题**，是我方初次调用方式不对——直接用 `.venv/bin/python` 跑 pytest，
   但没把 `.venv/bin` 放进 PATH，测试里通过 PATH 查找 `deity` / `python` 命令时找不到
   （`FileNotFoundError: 'python'`）。按第 2 节的正确方式重跑后 4 个全部通过，
   最终 584 通过、0 失败。教训已记入本文：跑测试必须先激活虚拟环境。

## 五、遗留风险与后续

- **跨平台 CI 部分通过**：V1.0 验收四条中三条完全通过，一条部分通过——Linux 本机全过，
  Windows 矩阵已加入 CI 但本机无 Windows runner 未验证。按实施计划 §4.8 既定处理：
  先发 1.0.0 的 macOS/Linux 已验证版，Windows 修好后再发 1.0.1。
- **审批放宽只在内存**：CLI 重构的 `allow_session` / `/auto` 仅对当前会话、
  仅对（tool_name，workspace）生效，会话结束即失效，未动 `PermissionConfig`。
- **测试调用方式**：见第 3 节第 3 条，CI 与本地复现都应使用激活虚拟环境后的标准调用，
  不要直接用 `.venv/bin/python` 绕过 PATH。
