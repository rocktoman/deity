# V0.4 本地扩展使用说明

> 状态：实现说明。V0.4 发布结论以对应验收记录为准。

## 配置与目录

以下示例放在 `~/.config/deity/config.toml`。模型密钥只从指定环境变量读取；MCP server 只能是本机 stdio 进程，`command` 建议使用绝对路径。未启用的扩展不会加载或启动。

```toml
[model]
provider = "openai_compatible"
name = "your-model"
base_url = "https://your-provider.example/v1"
api_key_env = "DEITY_MODEL_API_KEY"

[extensions]
version = 1
mcp_enabled = true
skills_enabled = true
hooks_enabled = true

[mcp.servers.demo]
command = "/absolute/path/to/python"
args = ["/absolute/path/to/trusted_server.py"]
cwd = "."
env_names = ["SERVER_TOKEN"]
timeout_seconds = 15

[[hooks.registered]]
name = "deny_delete"
point = "BeforeTool"
kind = "policy"
callable = "deity.examples.v0_4_hook:deny_delete"
priority = 0
```

项目 Skill 放在 `<workspace>/.deity/skills/<name>/SKILL.md`，用户 Skill 放在 `~/.config/deity/skills/<name>/SKILL.md`。文件必须以简单 frontmatter 开始，包含与目录名一致的 `name` 和一行 `description`：

```markdown
---
name: example
description: 适用于某类明确任务
---
正文说明
```

模型起初只看到有界的 Skill 索引；只有明确调用 `load_skill` 才加载正文。`load_skill_resource` 要求本 Run 已加载该 Skill，且请求路径出现在其正文中。Skill 中的脚本不会自动运行。重名、越界路径、symlink 和超限内容会被拒绝。

第三方兼容示例：本地 server 见 `tests/fixtures/mcp_echo_server.py`，Skill 见 `examples/v0_4_skill/SKILL.md`，受信任 Hook 见 `src/deity/examples/v0_4_hook.py`。对应协议与故障断言位于 `tests/unit/test_mcp.py`、`tests/unit/test_skills.py`、`tests/unit/test_hooks.py` 及 X01–X06。Skill 索引总量上限为 8 KiB，单个正文或资源上限为 16 KiB，每个 Run 累计加载正文与资源上限为 64 KiB；MCP 最多配置 8 个 server，每个 server 最多 64 个工具。

## CLI 流程

```bash
deity mcp list --config ~/.config/deity/config.toml
deity mcp test --config ~/.config/deity/config.toml --workspace /path/to/repo
deity skills list --workspace /path/to/repo
deity skills inspect example --workspace /path/to/repo
deity run "使用 example Skill 分析项目" --config ~/.config/deity/config.toml --workspace /path/to/repo
```

`mcp test` 只启动、协商并检查工具 schema，不调用业务工具。首次启动 server 时会显示命令、参数、工作目录、环境变量**名称**与摘要；确认记录保存在本地 SQLite。启动配置变化后重新确认。每次 MCP 工具调用仍需单独批准；`shell/workspace_write = "auto"` 不授权 MCP。无交互审批入口时拒绝未受信任的启动或工具调用。

内部审计名为 `mcp:<server>:<tool>`；发给模型协议时使用稳定、安全的函数别名，收到完整调用后映射回内部名。MCP 描述、结果和 Skill 正文均属于低信任上下文，不改变 Deity 的权限策略。

MCP 授权绑定完整参数快照；参数在审批后变化会拒绝派发。允许传入 server 的环境变量值会从文本工具结果中替换为 `[REDACTED]`，server 的 stderr 不展示到 CLI 或报告。该处理不能约束 server 自身读取工作区或以其他形式泄露信息，因此仅配置可信的本地进程。

Hooks 只加载在配置中显式列出的 Python async 函数。导入模块会执行模块顶层代码，因此仅配置自己信任的已安装模块。Observer 接收不可变事实；Policy Hook 可 veto，不能把底层拒绝改为允许。Policy Hook 异常或超时会拒绝当前动作，Observer 异常被审计并隔离。Hook 决议、Skill 激活和工具结果保存在 Run 事件中。

## 恢复、回退和验证

外部调用的结果若在断线或进程崩溃后无法确认，会标记 `unknown`，不得自动重放。Skill 内容、Hook 源代码或扩展配置变化会改变恢复指纹；`deity runs inspect` 会说明为何不能安全续跑。SQLite v2→v3 正向迁移前生成并验证 `.v2.bak`，旧事件仍可读取。

回退扩展时将三个开关设为 `false`，保留数据库和审计事实，运行既有 E01–E08、R01–R06 及 X06。若需恢复旧数据库，先复制 `.v2.bak` 到隔离路径、验证可打开且历史 Run 可读，再决定实际切换；不要对现用数据库执行删表式逆迁移。

```bash
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy src
uv run --locked pytest -q
uv run --locked python -m evals.runners.runner
uv run --locked python -m evals.runners.reliability
uv run --locked python -m evals.runners.extensions
```

本地工作区路径检查不是操作系统沙箱。真实模型验收应在隔离 fixture、明确密钥和预算下单独运行，不能代替上述确定性测试。
