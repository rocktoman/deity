# V0.7 只读委派使用与回退

> 只读委派默认关闭。子 Agent 只能读取/搜索工作区；这属于应用权限控制，不是操作系统沙箱。

## 启用

在用户 TOML 配置中显式设置：

```toml
[multi_agent]
version = 1
enabled = true
max_depth = 1
max_children = 4
max_concurrency = 2
max_result_chars = 4000
```

运行 `deity run "分析这个项目中两个模块的职责" --config /path/to/config.toml --workspace /path/to/repo`。模型可以调用 `delegate`，一次提交最多 `max_children` 个只读任务，每个任务必须指定目标、工具白名单、轮次、工具次数和截止时间。子任务仅支持 `read_file`、`list_files`、`glob`、`grep`；Shell、Git、MCP、Skills、Hooks、Verification 和写工具均不可用。父 Run 的剩余预算不足时委派被拒绝。模型生成的总结只是摘要，证据以持久化的工具调用和 evidence ID 为准。

运行后用 `deity runs tree <root-run-id> --db /path/to/deity.db` 查看委派 ID、父子 Run ID、状态、摘要及证据 ID。原始子任务执行仍在 SQLite 事件与工具审计中，CLI 不把它们全部注入父上下文。`partial` 表示同批子任务有成功也有失败；父 Run 自身终态仍按旧状态机记录。

## 取消、恢复与回退

父 Run 取消时，Application 向活动子 Loop 级联取消；排队中尚未启动的子 Run 标为 cancelled。崩溃重启后，失去所有者的活动子 Run 标 interrupted，不自动重放。包含委派的父 Run 恢复判定为 `manual_review`，应先检查 `runs tree` 和各子 Run 事件，再决定人工处理。

关闭 `[multi_agent].enabled` 停止新委派，旧单 Agent 路径保持可用；保留 SQLite v6 委派事实供审计。若旧二进制必须使用 v5 数据库，先停止 Deity，备份当前 v6 库，仅在**隔离路径**检查 `.v5.bak` 的 `PRAGMA integrity_check` 与版本后恢复；不要在当前库上删表逆迁移。严重越权、重复未知副作用或预算穿透时，立即关闭开关并阻断发布。

## 验证

本地门禁：`uv run ruff check .`、`uv run ruff format --check .`、`uv run mypy src`、`uv run pytest -q`、`uv run --locked python -m evals.runners.multi_agent`。旧 E/R/X/A/S 评估也需全量回归。真实模型和远程 CI 分别记录，不用确定性评估代替。
