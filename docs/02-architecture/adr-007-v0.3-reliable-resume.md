# ADR-007：V0.3 从安全边界恢复长任务

状态：拟采纳；供 V0.3 实施评审。基线：[V0.2 架构](deity-harness-v0.2.md)、[ADR-006](adr-006-aiosqlite-v0.1.md)。

## 决策

1. **原 Run 终态不复活。** 进程遗留的 Run 经所有权核查后标记 `interrupted`；用户显式执行 `deity resume <run_id>` 时，创建关联原 Run 的新 Run。只有持久化的完整、安全边界可作为恢复起点。V0.3 不承诺在任意指令或 Shell 内部续跑。
2. **Checkpoint 是持久化投影，不是工具重放脚本。** 完整模型响应、每个工具 intent 与 outcome、模型可见消息先以事务落库；在整批工具调用结束且无待决审批/未知副作用时，写入包含上下文与事件游标的 Checkpoint。恢复只读取已提交事实。原始审计记录保留，压缩仅改变后续模型输入。
3. **结果未知时停止。** 已写 intent 但没有可信 outcome 的工具，标记 `unknown`。任何有副作用或执行类工具都必须人工核对，不按 `call_id` 重试。即使是只读调用，也不得伪造旧结果；新 Run 可以重新读取并产生新 `call_id`。
4. **单所有者用 SQLite 租约与 epoch 防护。** 租约续约、状态更新和下一步派发均检查 epoch；租约过期只触发核查，不证明旧进程已经停止。旧执行进程或副作用状态不明时禁止自动接管。
5. **重试仅覆盖未提交的模型请求及可证明无副作用的事务。** 取消、认证/权限/协议错误不重试；模型响应已有语义增量或工具 intent 后，不自动重发同一轮。持久化提交结果不明时，先按稳定操作 ID 查询，再决定后续动作。
6. **取消是全链路信号。** Application 发起取消，Core 停止新模型/工具动作，适配器关闭流，执行层清理受控进程；关键状态提交使用受限的清理窗口完成。外部副作用无法撤销时如实记录 `unknown`。

## 理由与边界

V0.2 的 `interrupted` 是审计终态，直接改回 `running` 会破坏状态不变量。SQLite 只能保证本地事务，不能与文件系统、Shell 或模型 API 组成原子事务，因此不能宣称外部副作用“恰好一次”。Checkpoint 能保证**已提交状态的可重建性**；它不能保证未提交外部动作的结果。租约防止正常情况下的双 owner，但不能代替进程隔离或 OS 沙箱。

## 实施与验证要求

先迁移存储和事件协议，再开放 `resume`。迁移前备份并做恢复演练；旧事件只读兼容。用独立进程在 intent 前、intent 后、执行后未记 outcome、outcome 提交后、Checkpoint 提交前/后注入崩溃，验证每个位置的判定与零自动重复副作用。完整门禁见 [V0.3 实施文档](../03-development/v0.3-reliable-runtime-implementation.md)。
