# ADR-006：V0.1 使用 aiosqlite 保存会话与执行事件

状态：已采纳（V0.1 初版）

## 决策

使用 `aiosqlite` 和单连接写锁实现 SQLite 存储。关键状态、工具调用占位、结果与事件在事务中写入；工具完成事件在结果提交后才可查询。启用 WAL、foreign keys 与 busy timeout。重启时将遗留运行标为 `interrupted`，不自动重放工具。

## 理由与代价

当前本地 CLI 的并发需求有限，单连接写锁能保持每 Run 事件序号与工具结果顺序明确，代码量小于自建写队列。它不能提升 SQLite 的写吞吐；若以后需要多个进程同时写入，应重新评估连接、锁和所有权策略。数据库事件用于审计，不构成任意位置恢复能力。

## 验证

临时 SQLite 集成测试覆盖重复 `call_id`、结果与事件一致性、事务失败回滚、重开后的中断标记和 Agent Loop 工具结果落库。发布前继续执行完整 M4/M5 门禁。
