# ADR-013：V0.7 受控只读委派

状态：已采纳（V0.7 实施基线）。依据：[V0.7 设计](../05-roadmap/deity-v0.7-design.md)与[实施计划](../03-development/v0.7-implementation-plan.md)。

## 决策

1. 一个子 Agent 是独立 Run，继承父级工作区，但使用独立任务文本、上下文、租约、工具集合与预算。委派谱系另存于 `delegations`，不复用表示 checkpoint 续跑的 `run_lineage`。
2. 父 Run 的可委派预算按模型轮次、工具次数、输入和输出 token 上限原子预留。父 Run 自身已经消耗的量先扣除；缺失 usage 的 token 视为未知并阻止进一步分配该项。子 Run 的 deadline 不得晚于父级 deadline。预算预留、子 Run 创建及委派 intent 是一个 SQLite 事务；重复委派 ID 不再创建新 Run。
3. V0.7 只读 profile 仅暴露经过审查的 `read_file`、`list_files`、`glob`、`grep`。每次调用还要在分发层校验。Git 工具、Shell、MCP、Skills、Hooks、Verification、文件修改及 Docker 工件回传不可用于子 Agent。父级权限不能由模型消息或仓库文件扩大。
4. 子任务运行由 Application 层的 `asyncio.TaskGroup` 和有界 FIFO 队列协调。单个 `AgentLoop` 仍只持有一个 Run。父级取消/终止级联取消子任务；失败按子 Run 记录，聚合 `partial` 只用于委派结果，不更改旧 Run 终态含义。
5. 结果仅返回有界摘要及在存储中验证属于该子 Run 的 evidence ID。子上下文不复制父对话或完整工具日志。事件含版本、父子 ID、预算与状态；SQLite v5→v6 迁移前备份并验证 `.v5.bak`。恢复时遗留运行态子 Run 标 interrupted，未知副作用不自动重放。
6. `[multi_agent]` 默认关闭。关闭时不改变旧请求指纹和单 Agent 路径。严重越权、预算穿透或未知副作用重放立即关闭功能并阻断发布。回退保留 v6 审计事实；旧程序只能在隔离路径验证并使用 v5 备份。

## 范围与理由

仅使用 Python 标准库 `asyncio` 和现有 SQLite、模型与工具端口；不新增运行依赖。并发写入只在隔离 worktree fixture 探索，普通 CLI 不暴露，不自动合并。工作区只读约束是应用层权限，不是操作系统沙箱。上述选择保持 `interfaces → application → core ports ← adapters` 的依赖方向，并让父子预算及谱系在崩溃后可审计。
