# ADR-014：V0.8 统一客户端协议走 SQLite 轮询

状态：已采纳（V0.8 实施基线）。依据：[V0.8 设计](../05-roadmap/deity-v0.8-design.md)与[实施计划](../03-development/v0.8-v1.0-implementation-plan.md)第 2 节。

## 决策

1. CLI 与 TUI 共用 Application 层 `ClientService`（`start_run/subscribe_events/approve/cancel/resume`），不各自直连 RunService 或 SQLite。事件契约在 `core/contracts/client.py`：`ClientEvent`（`seq`、`run_id`、`schema_version=1`、`kind`、`payload`、`created_at`）、`RunHandle`、`EventSubscription`、`ApprovalRequest`、错误码（`run_not_found` / `approval_not_found` / `already_decided` / `subscription_closed` / `slow_consumer`）。
2. 事件订阅走 SQLite 轮询（`adapters/events.py` 的 `SQLiteEventSubscriber`，快照 + 只读轮询，默认 100ms、上限 1s 退避），不新增消息队列。理由：`events` 表已有 `(run_id, sequence)` 唯一约束与 `idx_events_run_seq` 索引，`SQLiteSessionRepository.events()` 可按序读事件；复用已有持久化事实，无新依赖、无新进程、可回放；订阅是只读的，不写事件。
3. 断线重连用 `after_seq` 续订：订阅先给快照再跟随增量，`seq` 不递增的乱序事件不应用；重连不重复执行工具（工具执行以 `tool_executions.call_id` 唯一约束为准）。
4. 慢消费者用有界队列（默认 100，可配）：队列满则断开订阅并报 `slow_consumer`，不丢事件后静默续跑；Run 本身不受影响。
5. 审批去重以 `approval_id` 为准：同一 `approval_id` 的重复决定返回首次结果，不同决定报 `already_decided`；审批等待用 `asyncio.Event`，不忙轮询。`RunService` 保留同步 `approve` 回调（CLI 兼容），另持可等待的 `ApprovalPort`；`ClientService` 注入异步实现，桥接时经 `run_coroutine_threadsafe` 把请求发回事件循环。
6. `RunService.run()` 接受可选的预生成 `run_id`（经 `create_run(request, run_id=...)` 落库后走 `loop.run_created`）与可选 `event_sink`，使 `ClientService.start_run` 能在 Run 启动前返回可用句柄；`wait()` 把取消转为 `CANCELLED` 终态结果。

## schema_version 演进规则

1. 当前版本为 `schema_version=1`，事件 payload 内含该字段；读取时缺失视为 1。
2. 字段只增不减：新版本可新增可选字段，不得删除或改变已有字段含义；旧事件只读兼容，不迁移写入。
3. 破坏性变更必须先写 ADR 并升级主版本号；`schema_version` 变化时，订阅方按版本分发，未知版本只读并标注，不静默丢弃。
4. 配置格式同步带版本（`version: int = 1`），未知段报错；`[tui]`/`[doctor]` 段默认关闭。

## 范围与理由

仅使用 Python 标准库 `asyncio` 与现有 SQLite、模型与工具端口；不新增运行依赖。Textual 仅为可选 extra（`tui`），未安装时 CLI 正常使用。轮询延迟上限 1s 是已知限制：订阅不是实时推送，TUI 渲染背压只丢弃已渲染的旧流式增量并标注，不阻塞 Run。

## 回退

关闭 `[tui].enabled` 即回纯 CLI；删 extra 与 `interfaces/tui` 即可移除 TUI；`ClientService` 停用后 CLI 仍走原有 `RunService` + 同步审批路径。发生严重权限或重复副作用缺陷时立即禁用相关功能并阻断发布。
