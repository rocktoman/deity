# ADR-011：V0.5 高级编码工作流边界

状态：已采纳。依据：[V0.5 设计](../05-roadmap/deity-v0.5-design.md)与[V0.5 实施计划](../03-development/v0.5-implementation-plan.md)。

## 决策

1. Plan 模式由 Tool Runtime 的 `ExecutionPolicy` 强制只读。仅允许工作区读取、搜索、Git 只读检查、Code Intelligence、Skill 读取和 `submit_plan`；写入、删除、Shell、未知工具及 MCP 业务工具在 durable intent 前拒绝。
2. `deity build --plan` 是显式批准动作。系统校验计划 hash、需求 hash、TTL 和工作区快照，并在同一 SQLite 事务中批准计划、创建新 Build Run 和写入唯一关系；不原地提升 Plan Run 权限。
3. V0.5 Code Intelligence 使用标准库与现有 `rg` 的 lexical backend。结果明确区分 definition candidate 与 textual reference；缓存位于 XDG cache，按工作区身份、backend version、路径、mtime、size 和内容 hash 失效。
4. Build 启动时捕获 Git HEAD、porcelain v2、submodule 与文件 preimage。初始 dirty path 默认拒绝修改，只接受 `--allow-dirty` 对相对普通文件的逐路径授权；不自动 commit、stash、reset 或 clean。
5. 安全补丁只处理有界 UTF-8/UTF-8 BOM 文本，保持换行风格，要求唯一上下文和未漂移 preimage，并以临时文件、fsync、`os.replace` 原子提交。二进制、symlink、submodule、冲突和未知编码默认拒绝。
6. Verification 探测器生成固定 argv，执行器不接受模型自由 Shell 字符串。权限默认为 `ask`，支持 `auto/deny`；每项具有 cwd、环境白名单、超时、输出上限、取消清理和 Evidence。
7. 主审计库正向迁移 SQLite v3→v4，迁移前创建并验证 `.v3.bak`。Plan、Plan→Build、WorkspaceSnapshot、ChangeSet 和 Verification 使用专用事实表；索引缓存不进入主库。
8. 所有新功能默认关闭。关闭后 V0.4 的 CLI、工具集合、恢复指纹和扩展路径保持兼容；旧事件只读，不提供删表式逆迁移。

## 依赖与替代方案

V0.5 必选实现不新增运行时依赖，复用 Python 标准库、Git CLI、`rg`、现有 SQLite 与进程执行能力。tree-sitter 或 LSP 仅在 A04-A06 固定 fixture 的 lexical 精度经修正规则后仍不达标时另提 ADR；届时必须记录用途、许可证、维护状态、锁定版本、安全风险、替代方案和移除成本。

## 可靠性与回退

Plan 批准、工具副作用和验证命令继续遵守 V0.3 intent/outcome/unknown 规则；未知结果不自动重放。回退时依次关闭 verification、git guard、code intelligence 和 plan/build 开关，保留 v4 审计事实只读，并在隔离路径验证 `.v3.bak`。任何只读绕过、用户改动覆盖、重复未知副作用或证据夸大均阻断发布。
