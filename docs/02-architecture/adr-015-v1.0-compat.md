# ADR-015：V1.0 冻结公开 API 与兼容承诺

状态：已采纳（V1.0 实施基线）。依据：[V1.0 设计](../05-roadmap/deity-v1.0-design.md)与[实施计划](../03-development/v0.8-v1.0-implementation-plan.md)第 4.2 节。

## 冻结清单

### 1. 公开 Python Protocol 与类型

`src/deity/core/contracts/__init__.py` 的 `__all__` 即公开 API 清单（快照见
`tests/unit/test_public_api_compat.py`，`COMPAT_VERSION = 1`）。冻结内容：

- Protocol：`ModelProvider`（`capabilities` / `stream`）、`ToolDispatcher`（`dispatch`）、
  `SessionRepository`（`create_run` / `set_status` / `record_model_turn` /
  `context_messages` / `save_checkpoint` / `latest_checkpoint` / `claim_tool` /
  `record_tool` / `mark_tool_unknown` / `record_hook_event` / `record_step` /
  `record_usage` / `record_model_attempt` / `record_context_compaction` /
  `acquire_lease` / `renew_lease` / `release_lease`）、`EventPublisher`（`publish`）、
  `ApprovalPort`（`request_approval`）、`EventSubscription`（异步迭代器 + `close`）。
- DTO：`AgentRequest` / `AgentResult` / `RunBudget` / `RunLease` / `RecoveryDecision` /
  `ToolCall` / `ToolResult` / `ModelEvent` / `ModelRequest` / `ModelCapabilities` /
  `RunStatus`，以及 `ClientEvent` / `RunHandle` / `ApprovalRequest` / `ClientError`。
- 应用层协议：`ClientService`（`start_run` / `subscribe_events` / `approve` /
  `cancel` / `resume` / `wait` / `collect` / `pending_approvals`）。
- 冻结含义：方法名、参数名、参数顺序、返回值类型、错误码（`run_not_found` /
  `approval_not_found` / `already_decided` / `subscription_closed` / `slow_consumer`）
  在 1.x 内不变；新增只能加可选参数或新方法，不得改现有签名含义。

### 2. 事件 schema

- 当前版本 `schema_version=1`，事件 payload 内含该字段；读取时缺失视为 1。
- 字段只增不减：新版本可新增可选字段，不得删除或改变已有字段含义；
  旧事件只读兼容，不迁移写入（回放时未知版本只读并标注 `schema_mismatch`）。
- `ClientEvent` 字段冻结为 `seq` / `run_id` / `kind` / `payload` /
  `schema_version` / `created_at`。

### 3. 配置文件

- TOML 配置带版本字段 `version: int = 1`；未知段报错（严格校验，不静默忽略）。
- 配置段只增不减：`[run]` `[permission]` `[model]` `[extensions]` `[mcp]`
  `[coding]` `[code_intelligence]` `[git_guard]` `[verification]` `[sandbox]`
  `[multi_agent]` `[tui]` `[doctor]` `[eval]`；删除或改名一个段即破坏性变更。
- 优先级不变：CLI > project（`./.deity/config.toml`）> user
  （`~/.config/deity/config.toml`）> default。

### 4. SQLite 迁移规则

- `schema_migrations` 表记录已应用版本；迁移只前向，不提供降级迁移。
- 打开旧库前先在同目录写 `.vN.bak` 备份并校验备份版本（既有 `_backup_v1` /
  `_backup_v2` / `backup_v3` / `backup_v4` / `backup_v5` 模式）；备份校验失败即拒绝迁移。
- V0.7 时代库（`schema_migrations` 最大版本 6，fixture
  `tests/fixtures/legacy-v07.db`）在 1.0.0 下打开后可读、事件可查；
  迁移测试见 `tests/integration/test_migration.py`。
- 1.0.0 不新增 schema 迁移：打开 v6 库即为最新，不写新版本号。

## semver 与弃用窗口

- 版本号遵循 semver：`1.0.0` 起，破坏性变更只进主版本号；
  新功能（向后兼容）进 minor；修复进 patch。
- 破坏性变更至少提前一个 minor 版本预告：在 CHANGELOG 与兼容政策中写明
  废弃内容、替代方案与移除版本；在预告期内旧 API 仍可用（可打印弃用警告，
  不得静默改行为）。
- 冻结清单本身的任何改动都必须先改本 ADR，并同步更新
  `tests/unit/test_public_api_compat.py` 的快照；快照测试失败时，
  先判断是 ADR 未更新还是实现越界，不直接改快照蒙混通过。

## 回退

- 发现冻结后仍有破坏性 API 缺口：不悄悄改，加 ADR 并推迟到 1.1.0
  （或按 semver 进 2.0.0 预告）。
- 旧库升级失败：用 `.vN.bak` 备份恢复，见
  [升级/回滚指南](../03-development/upgrade-rollback-guide.md)。
