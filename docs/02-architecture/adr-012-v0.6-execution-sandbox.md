# ADR-012：V0.6 执行沙箱边界

状态：已采纳（实施基线）。依据：[V0.6 设计](../05-roadmap/deity-v0.6-design.md)及[实施计划](../03-development/v0.6-implementation-plan.md)。

## 决策

1. Core 定义执行后端 Protocol 与能力契约；Application 协调授权、持久化与后端生命周期；Docker adapter 只执行受控 I/O，不决定权限。
2. V0.6 仅接入 shell 和 Verification。Plan 模式的 shell 拒绝、工具参数校验、审批、工作区边界和已有 ToolClaimed 继续生效。
3. Docker 通过本地 CLI 的 argv 调用，不使用 shell 拼接或 Python Docker SDK。仅支持本机 daemon；拒绝远程 context/DOCKER_HOST。普通运行不拉取镜像，镜像必须以 digest 或本地 image ID 固定。
4. 容器只挂载复制出的 staging 工作区。默认禁网、非 root、只读根文件系统、丢弃全部 capabilities、no-new-privileges，并限制 CPU、内存、PID、tmpfs、时限及输出。不能挂载 Docker socket、宿主 home 或 Deity 数据库。
5. Docker 不可用、镜像缺失、能力不足或 required 策略不满足时拒绝，绝不回退宿主。容器不是完全安全边界；本地 Docker daemon 与宿主内核仍是信任前提。
6. 工件先由宿主扫描 staging 建立清单，再经已有 Git Guard、dirty allowlist、preimage、权限与 ChangeSet 审核。Verification 固定丢弃工件。多文件回传逐文件记录，允许 partial/unknown，不宣称文件系统级事务。
7. intent 在副作用前提交；execute、collect、apply、cleanup 分开记录。未知结果不自动重放，恢复需根据持久化容器 ID 与 label 人工协调。
8. SQLite v4→v5 正向迁移，迁移前验证 `.v4.bak`；旧事实只读。沙箱默认关闭，关闭时原路径和旧请求指纹保持一致。

## 依赖与威胁

不新增 Python 运行依赖，使用 Docker CLI/Engine 作为可选外部前置。相比 Docker SDK，此方案减少 Python 依赖，但必须严格限定 CLI argv、daemon context 和容器身份。Docker CLI/Engine 的许可证、版本兼容、维护与安全公告应在候选验收时记录；本轮以本地 29.5.2 为开发基线。Podman/OCI CLI 暂不支持，未来可通过后端 Protocol 替换。关闭开关可移除 Docker adapter 而不改变核心契约，v5 审计事实仍须可读。

威胁包括恶意镜像、daemon 高权限、内核逃逸、符号链接/特殊文件、挂载错配、环境变量泄漏、网络外连、资源耗尽、结果丢失与孤儿容器。上述约束降低风险，但不保证抵御恶意 daemon 或内核漏洞。严重权限绕过、秘密泄漏、用户改动覆盖或重复未知副作用均阻断发布。

## 回退

关闭 `[sandbox].enabled`，停止新增容器；按已记录 execution ID 精确协调活动容器和 staging。保留 v5 事实只读。旧二进制需要旧库时，先停止进程、备份 v5，再在隔离路径验证并恢复 `.v4.bak`，不做删表逆迁移。
