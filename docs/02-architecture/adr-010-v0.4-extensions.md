# ADR-010：V0.4 扩展边界

状态：实施中。依据：[V0.4 设计](../05-roadmap/deity-v0.4-design.md)与[实施文档](../03-development/v0.4-extensible-harness-implementation.md)。

## 决策

1. 扩展配置版本从 1 开始，三个开关默认关闭。扩展身份由类别、来源、稳定名称和内容/协议版本确定；事件 payload 显式携带 `schema_version=1`。内部 MCP 名称为 `mcp:<server>:<tool>`；模型协议使用稳定哈希别名，避免函数名字符限制。
2. MCP 仅接本地 stdio。外部工具默认 `unknown_effect`，每次完整调用单独审批；本地工具 `auto` 不传递给 MCP。server 启动按命令、参数、工作目录和环境变量**名称**摘要确认，摘要变更后重新确认。
3. 模型先读取 Skills 有界索引，再显式选择加载正文。Skill、MCP 返回值和仓库 `AGENTS.md` 均为低信任上下文，不能授权工具。Skill 脚本不自动执行。
4. Observer 只读；Policy Hook 只能 veto。Policy Hook 异常或超时拒绝当前动作；Observer 异常记录后隔离。Hook 决议排序稳定且可审计。
5. 扩展配置/内容摘要进入恢复预检。漂移时停止安全续跑，不能继承先前审批。MCP 调用沿用 V0.3 intent/outcome/unknown 规则，未知副作用永不自动重放。

## 兼容、迁移与回退

Core 只增加端口与注入点；MCP SDK 只在 Adapter。配置未知版本拒绝加载。SQLite v3 新增 `mcp_launch_trust`，以 server 名称和启动摘要保存授权；迁移前备份 v2 并验证，旧事件保持只读，不删表回滚。三个开关分别关闭后仍可使用 V0.3 基础能力。任何权限绕过、重复未知副作用或秘密泄漏阻断发布。

## 依赖记录

`mcp==2.3.0` 用于 stdio 协议、会话与协商；自写 JSON-RPC 是替代方案，但协议兼容与维护成本更高。SDK 为 MIT 许可，锁定版本与传递依赖见 `uv.lock`；安全公告需在升级时复核。移除该依赖的成本是替换 stdio Adapter 与协议测试，不影响 Core 契约。`jsonschema==4.26.0` 用于校验远端工具参数 schema 和完整调用参数，许可证为 MIT；替代方案是自行维护 JSON Schema 子集，风险是协议兼容和校验遗漏。两个依赖都仅为本版实际 MCP 功能引入。Skills 元数据使用标准库和已有 Pydantic，无额外解析依赖。
