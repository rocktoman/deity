## Anthropic 失败根因与修复

**现象**：7 个 Anthropic 适配器测试在 `AnthropicProvider.__init__` 即崩溃，`httpx2.InvalidURL: Invalid port: ':1]'`。

**根本原因**（逐层验证，非推测）：

1. 本机 `NO_PROXY` 同时包含裸写 `::1` 与方括号写 `[::1]`（及 `[fd8b:…]` 段）。
2. anthropic 2.3.0 自带的 `get_environment_proxies()`（`anthropic/_utils/_httpx.py`）是旧版 httpx 逻辑的复刻，缺少方括号 IPv6 分支：`[::1]` 经 `is_ipv6_hostname`（`ipaddress.IPv6Address("[::1]")` 抛错）判为非 IPv6，又不匹配 `localhost`，落入通配 `else` 分支，拼出 `all://*[::1]`。
3. SDK 的 `_DefaultAsyncHttpxClient` 无条件用该函数构造 env mounts 并传给 `httpx2.AsyncClient`，后者 `URLPattern("all://*[::1]")` 解析时把端口读成 `':1]'` 而报错。httpx2 自身的同名函数有方括号分支与不可解析条目丢弃逻辑，不会出错；OpenAI 3.41.0 不自带该函数，故只有 Anthropic 失败。
4. 先前“去掉代理环境变量后仍复现”的说法不准确：触发条件是 `NO_PROXY` 里的方括号 IPv6，不是 `HTTP_PROXY` 本身；只清代理变量不清 `NO_PROXY` 仍会复现。

**改法**（修代码，未动 SDK、未隔离测试环境）：`src/deity/adapters/model/anthropic.py` 改为传显式 `http_client=httpx2.AsyncClient(...)` 构造 `AsyncAnthropic`，绕过 SDK 有问题的自带解析；新客户端沿用 httpx2 自身的代理解析（保留代理支持，坏条目自动丢弃），超时/连接限制沿用 SDK 默认值（`Timeout(600, connect=5.0)`、`Limits(1000/100)`、`follow_redirects=True`）。`httpx2>=2.0,<3` 由传递依赖改为直接依赖记入 `pyproject.toml`（与 anthropic 2.3.0 要求的 `httpx2<3,>=2.0.0` 一致），`uv.lock` 同步更新。

**验证**：新增回归测试 `test_anthropic_provider_survives_bracketed_ipv6_no_proxy`（`NO_PROXY` 含 `[::1]` 时构造成功）；7 个旧失败测试全部通过；全量 pytest 407 通过、0 失败。

**已试过的其他路径**：只清 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY` 不解决问题（触发在 `NO_PROXY`）；升级 anthropic SDK 未采用——2.3.0 是锁定版本，升级影响面未评估，且本修复不依赖上游改动；仅在测试里清理 `NO_PROXY` 未采用——那会掩盖生产环境同样会触发的构造崩溃。

## 实施中发现并修复的回归

1. `deity run` 改走 `ConfigResolver` 后，交互 CLI 测试 monkeypatch 的 `cli.load_config` 被绕过，7 个交互测试失败。修复：`ConfigResolver.resolve` 接受可注入的 `loader`，CLI 传入本模块的 `load_config`。
2. `ClientService` 用第二连接轮询 Run 行：`SQLiteSessionRepository.open` 先做 `PRAGMA journal_mode=WAL`、后设 `busy_timeout`，并发打开撞上 Run 写事务即报 `database is locked`。修复：`start_run` 改用 `on_run_created` 事件通知，不再另开连接轮询；订阅期间持持久连接；`busy_timeout` 移到 `journal_mode` 之前。
