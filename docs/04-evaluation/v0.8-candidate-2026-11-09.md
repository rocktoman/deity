## 实施中发现并修复的回归

1. `deity run` 改走 `ConfigResolver` 后，交互 CLI 测试 monkeypatch 的 `cli.load_config` 被绕过，7 个交互测试失败。修复：`ConfigResolver.resolve` 接受可注入的 `loader`，CLI 传入本模块的 `load_config`。
2. `ClientService` 用第二连接轮询 Run 行：`SQLiteSessionRepository.open` 先做 `PRAGMA journal_mode=WAL`、后设 `busy_timeout`，并发打开撞上 Run 写事务即报 `database is locked`。修复：`start_run` 改用 `on_run_created` 事件通知，不再另开连接轮询；订阅期间持持久连接；`busy_timeout` 移到 `journal_mode` 之前。

## 已知限制

- TUI 仅在安装 Textual（`uv sync --extra tui`）且 `[tui].enabled = true` 时可用；录制回放不含真实终端像素。
- TUI 的恢复操作目前是回调占位（`on_cancel`/`on_approve`/`on_deny` 需调用方注入），`TuiApp` 未直接接 `ClientService.resume`；完整 TUI 内恢复闭环待后续迭代。
- 事件轮询默认 100ms、上限退避 1s；订阅不是实时推送。
- 7 个 Anthropic 既有失败保持原样（见基线说明）。
- 真实模型 L3（`python -m evals.runners.l3_candidate`）需密钥：NOT_RUN。
