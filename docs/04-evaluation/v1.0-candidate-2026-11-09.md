## 诚实说明与已知限制

- **V1.0 修复的两处真实缺口**（均由新测试先暴露、再改代码、重跑通过，不是只记录）：
  1. 存储层 `_redact` 原先只脱敏 `key=value` 形式的密钥，工具参数 `argv` 中的裸 `sk-…` token 会原样落盘进 `tool_executions.args_json`。已补裸 token 模式（`sk-` / `ghp_` / `gho_` / `github_pat_` / `AKIA`）脱敏，回归测试 `test_tool_args_with_secret_are_redacted_in_storage` 通过。
  2. 崩溃恢复路径 `SQLiteSessionRepository.open()` 把待决工具标 `unknown` 时不发 `ToolOutcomeUnknown` 事件（`set_status(INTERRUPTED)` 与 `mark_tool_unknown` 都会发），审计证据缺失。已补发每个待决工具的 `ToolOutcomeUnknown` 事件（`reason=process_interrupted`），回归测试 `test_kill_then_reopen_marks_interrupted_and_unknown` 通过。
  3. 计划文档写 `uv build --locked`，但 `uv build` 不接受 `--locked` 参数（只 `uv sync`/`uv run` 支持）。构建改用 `uv build --out-dir dist`，锁定校验由单独的 `uv lock --check` 承担（测试与 release workflow 已同步修正）。
  4. 旧测试 `test_help_and_version` 硬编码 `"0.1.0"`，版本升级后失败；已改为与 `deity.__version__` 动态比对。
- **Soak 孤儿进程计数的自观测陷阱**：首轮 `ps --ppid` 把 ps 自身也算作子进程，恒报 1 个孤儿。已改为用 `Popen` 取 ps 自身 PID 并排除；修正后 3 分钟与 10 分钟轮次孤儿进程均为 0。
- **Soak p95 波动**：10 分钟轮次 p95 70.87ms 高于 3 分钟轮次 48.74ms，因 10 分钟轮次期间本机并行跑了演示脚本与测试，CPU 争用所致；p95 不是通过性指标，不作泄漏结论。泄漏判定只看 RSS 增长（-11.02 MB）与孤儿进程（0）。
- **RSS 负增长说明**：10 分钟 soak RSS 从 115.07 MB 降到 104.05 MB，150 秒后平台期约 102.3–102.5 MB；起始值含进程启动与分配器预热，平台期后无增长，故判无泄漏。阈值 64 MB 据此固化。
- **崩溃恢复的真实语义**：带未决副作用的崩溃 Run，`create_resumed_run` 拒绝续跑（`ValueError: unresolved side effect requires review`），`deity runs inspect` 结论为 `manual_review` / `unresolved_tool`；须人工复核后才能处理，系统不自动重放未知副作用。无未决工具的崩溃可从崩溃前 checkpoint 续跑，新 Run 不含旧工具记录。
- **示例 A/B 实验 off/on 耗时差是运行波动、不是 compaction 效果结论**——见 V0.9 验收记录。
- **本地工作区限制不是 OS 沙箱**；Windows CI 未在本机验证；`uv audit` 在本机 120 秒内拉不到 advisory 数据库、无结果，供应链扫描以 `pip-audit --strict` 为准。
- 全量 pytest 有 1 个警告（非失败）：aiosqlite 在既有存储测试收尾时报 `ResourceWarning` / `PytestUnhandledThreadExceptionWarning`（事件循环已关闭），与 V1.0 改动无关，属既有抖动。
