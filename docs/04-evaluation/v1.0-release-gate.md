## Soak 阈值（首轮实测后固化）

- 采样方法：Linux `/proc/self/status` VmRSS（当前值）；阈值默认 64 MB（10 分钟）。
- 首轮实测：3 分钟 soak，4670 次迭代，RSS 114.99 → 119.46 MB，
  增长 4.47 MB，30 秒后 RSS 平台期约 118–119 MB（分配器预热后平稳，
  无线性泄漏），事件 65380 行，孤儿进程 0，p95 48.74ms，通过。
- 10 分钟实测（2026-11-09，`evals/reports/soak.json`）：12728 次迭代，
  RSS 115.07 → 104.05 MB，增长 **-11.02 MB**（负增长：150 秒后 RSS
  平台期约 102.3–102.5 MB，内存被释放回系统），峰值 118.74 MB，
  事件 178192 行，孤儿进程 0，均值 47.13ms、p95 70.87ms，通过。
  p95 高于 3 分钟轮次（48.74ms）是因为 10 分钟轮次期间本机并行跑了
  演示脚本与测试，CPU 争用所致；p95 不是通过性指标，不作泄漏结论。
- 阈值 64 MB 固化：10 分钟实测增长为负，阈值留有充足余量；
  若未来增长超 64 MB 即判失败并调查，不放宽阈值蒙混通过。

## Known Limitations

- **本地工作区限制不是 OS 沙箱**：未启用 Docker 时，Shell 与文件工具以用户权限
  在宿主机执行，只受路径与审批限制；需要隔离请启用 Docker 沙箱后端。
- **Windows CI 未在本机验证**：本机无 Windows runner；CI 矩阵已加 `windows-latest`
  （含 choco 安装 ripgrep），首次跑通前记 NOT_RUN。
- **示例 A/B 实验 off/on 耗时差是运行波动、不是 compaction 效果结论**：
  见 V0.9 验收记录；实验机制本身（单变量校验、重复、全部变体/case 列出、
  标准库统计）已由单测与端到端测试覆盖。
- **Anthropic 适配器**：V0.9 基线时 7 个既有失败已在 v0.8–v1.0 周期内修掉
  （本轮基线：pytest 全量 0 失败）；见 V1.0 验收记录。
- **`uv audit` 在本机不可用**：120 秒内拉不到 advisory 数据库、无结果；
  供应链扫描以 `pip-audit --strict` 为准（本地实测 0 已知漏洞），`uv audit`
  为文档备选，不作为门禁。
- **回放**：`deity eval replay` 只读；写工具一律拒绝并记 `replay_blocked`。
